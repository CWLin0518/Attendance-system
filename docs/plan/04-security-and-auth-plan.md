# 04 - 帳號驗證與多角色權限 (RBAC) 升級計畫 (Security & RBAC Plan)

## 1. 目標與安全升級背景
為使系統能夠部署於正式企業環境，需從目前的無狀態快速切換身分，升級為具備身分驗證、密碼保護與角色權限隔離（Role-Based Access Control）之架構。

---

## 2. 角色權限體系矩陣 (RBAC Matrix)

| 模組 / 功能 | 系統管理員 (Admin) | 部門主管 (Manager) | 一般員工 (Employee) |
| :--- | :---: | :---: | :---: |
| **員工打卡（上班/下班）** | ✅ | ✅ | ✅ (僅限本人) |
| **個人工時與月報查看** | ✅ | ✅ | ✅ (僅限本人) |
| **請假申請** | ✅ | ✅ | ✅ |
| **請假審核 / 駁回** | ✅ | ✅ (所屬部門) | ❌ |
| **排班行事曆覆蓋設定** | ✅ | ✅ (所屬部門) | ❌ (僅供查閱) |
| **員工名冊新增 / 刪除** | ✅ | ❌ | ❌ |
| **專案看板檢視** | ✅ | ✅ | ✅ |
| **專案任務建立 / 編輯** | ✅ | ✅ | ✅ |
| **系統重設資料庫** | ✅ (需二次確認) | ❌ | ❌ |

---

## 3. 技術架構方案

### 3.1 認證機制 (JWT Auth)
- **Token 設計**：使用 JSON Web Token (JWT) 作為無狀態認證憑證，儲存於 `HttpOnly` Cookie 或客戶端 `localStorage`。
- **過期與刷新**：Access Token 有效期 2 小時，支援自動刷新機制。

### 3.2 密碼儲存安全
- 採用 `bcryptjs` 進行密碼單向雜湊加鹽（Salt Rounds = 10），嚴禁明文儲存。

### 3.3 後端中介軟體 (Middleware)
- `authenticateToken`：驗證請求 Header 之 `Authorization: Bearer <token>`。
- `requireRole(['admin', 'manager'])`：依路由限制最低授權角色。

### 3.4 稽核日誌 (Audit Log)
- 紀錄關鍵敏感操作：員工資料異動、資料庫重設、排班強制覆蓋之操作者、時間與 IP 來源。
